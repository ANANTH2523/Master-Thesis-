# Raw Output Documentation — ThreMoLIA Experimental Datasets

## Overview & Purpose
This directory contains the **comprehensive, unmodified raw threat-modeling outputs** generated by ThreMoLIA across three experimental scenarios:
- `scenario1_raw_clean.csv` (106 threat findings)
- `scenario2_raw_clean.csv` (105 threat findings)
- `scenario3_raw_clean.csv` (117 threat findings)

These files serve as the authoritative record of the actual threat generation performed during the automated execution runs.

---

## Clarification Regarding Secondary Taxonomy Columns
The raw outputs presented here represent the comprehensive STRIDE-oriented threat generation results obtained from ThreMoLIA. STRIDE is the primary classification used in these outputs. 

Secondary taxonomy mappings such as:
- **MITRE ATT&CK**
- **OWASP Top 10 2025**
- **MITRE ATLAS**
- **OWASP Top 10 for LLM**
- **LINDDUN**
- **OWASP ML Security Top 10 2023**

were not populated in the corresponding raw generation output and have therefore not been artificially completed. These mappings are intentionally excluded from the supervisor-facing raw tables (`scenarioX_raw_clean.csv`) to avoid implying classifications that were not produced by the original run. Secondary mappings, where required by the thesis methodology, are handled as a separate documented analysis stage in the normalized thesis dataset (`scenarioX_validated.*`).

## Raw File Structure
The cleaned raw CSV files preserve 100% of the originally generated rows, threat IDs, descriptions, and STRIDE categories with the following columns:
1. `id`: Sequential threat identifier from the raw run (1 to N).
2. `element`: The affected architecture component, external entity, data store, or data flow.
3. `element_type`: Category of element (`External Entity`, `Process`, `Data Store`, `Data Flow`).
4. `stride`: Primary STRIDE category generated by ThreMoLIA.
5. `threat_description`: Verbatim text description of the threat scenario.
6. `mitigation`: Recommended mitigation strategy emitted during the run.
7. `SDL_stage`: Assigned Security Development Lifecycle stage (`Design`, `Implementation`, `Verification`).
8. `cvss_vector`: CVSS v3.1 vector string.
9. `cvss_score`: Calculated CVSS v3.1 base score.
